# Email delivery

Rally sends email sign-in links through Supabase Auth using Resend custom SMTP.
Email confirmation and PKCE remain enabled: a link must open in the browser that
requested it. SMTP configuration does not remove that requirement or enable
booking notifications.

## Configuration

The recorded Free setup uses a dedicated sender,
`Rally <signin@mail.rally.gowthamsarveswaran.com>`, and a sending-only key restricted
to that domain. SMTP uses `smtp.resend.com`, port 465, username `resend` and
verified TLS. Supabase Auth and Rally both limit email requests; the configured
Auth limit is 30 per hour. Keep usage within the provider account's current
limits, with no automatic paid overages.

Domain authentication is confined to `mail.rally.gowthamsarveswaran.com`.
Delivery TLS is enforced; click/open tracking and receiving are off. Existing
mail and unrelated DNS records are preserved.

Store the SMTP key in Supabase's private Auth settings and the ignored mode-600
`.env.smtp` file. It is not needed in the web runtime or repository. Changing
SMTP settings does not require an application redeploy. Preserve callback
allowlists, email confirmation, templates and application request quotas.

## Change or verify the setup

`scripts/configure-free-smtp.ts` defaults to a dry run. Apply mode requires the
explicit setup flag, matching project checkpoint and private configuration. It
changes only SMTP fields and the email limit, checks the saved configuration
and compares hashes of unrelated Auth settings.

`scripts/verify-smtp-connection.ts` checks TLS and SMTP authentication without
sending email. A successful connection or saved setting does not prove actual
routing or delivery. After a configuration change, wait for the running Auth
service to reload before an authorized delivery test. Inspect the actual sender
and delivery result rather than assuming the new settings are active.

## Restore a previous route

The recorded rollback clears only `smtp_host` through the Management API,
restoring built-in routing while leaving saved credentials private and dormant.
Do not change the email limit in that same operation; the API rejected that
combination during the recorded check. Restore custom SMTP before inviting
external users, because built-in routing has separate recipient restrictions.
Keep rollback and restoration sequential, and verify the running configuration.

## Recorded delivery evidence

On October 27, Resend marked the test email Delivered and the owner confirmed
sign-in in the same Chrome browser. The recipient was outside the Supabase
project team. A prior test used the old route before Auth reloaded; the runtime
reload and corrective delivery are retained separately.

On October 29 the owner also reported signing in and saving details on a phone.
The device, browser and chat/email transitions were not recorded. These results
do not establish independent friend-group or cross-device sign-in reliability.
