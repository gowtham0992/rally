# Free email sign-in

Rally uses Resend Free for Supabase Auth emails. The replacement test email was
marked **Delivered** in Resend, and the owner confirmed a successful sign-in in
the same Chrome browser. The tested recipient is outside the Supabase project
team. This verifies one desktop email-link flow; phone, chat-app and independent
friend-group testing remain open.

## Configuration

- Sender: `Rally <signin@mail.rally.gowthamsarveswaran.com>`.
- SMTP: `smtp.resend.com`, port 465, username `resend`, verified TLS.
- One sending-only API key restricted to the dedicated sending domain.
- Supabase Auth email limit: 30 per hour. Resend Free allows 100 per day and
  3,000 per month. The account has no card or enabled paid overages.
- Domain verified with one DKIM TXT and two Resend Forge CNAME records under
  `mail.rally.gowthamsarveswaran.com`. All 11 prior DNS records are unchanged.
- Domain delivery TLS is enforced. Click/open tracking and receiving are off.

Email confirmation, templates, callback allowlists, normal and managed sessions,
PKCE, application quotas and payment/privacy checks are unchanged. Magic links
must still be opened in the browser that requested them. The SMTP key is in
Supabase's private Auth settings and the ignored, mode-0600 `.env.smtp` file;
it is absent from the app runtime and Git. No application redeploy is needed.

## Verification and rollback

`scripts/configure-free-smtp.ts` defaults to a dry run and requires the explicit
setup flag, matching project checkpoint and private configuration. Its apply
mode changes only SMTP fields and the email limit, then checks the saved config
and hashes unrelated Auth settings. `scripts/verify-smtp-connection.ts` verified
TLS 1.3 and SMTP AUTH without sending mail.

The operational rollback was exercised by clearing only `smtp_host` through the
Supabase Management API. This restores built-in routing; saved credentials stay
private and dormant. Do not patch the email limit while disabling SMTP: the API
rejects that combination. Restore custom SMTP before inviting external users.
Built-in routing has provider recipient and rate restrictions.

Saved configuration is not sufficient proof of an active sender. The first
approved test used the built-in sender because Auth had not loaded the restored
configuration after the rollback check. Reapplying SMTP and observing the actual
Auth reload resolved it. A temporary 29-per-hour limit was observed in the
runtime, then 30 was restored and its reload observed before the separately
approved replacement test. Do not overlap rollback and restore operations.
Wait for the runtime reload before testing mail.

The replacement email was delivered through Resend and the owner confirmed
successful sign-in. Two email requests were made in total, each explicitly
approved; no friends were contacted and no payments were made. Existing test
account was reused. The local scripts passed TypeScript checking. The prior
194-test application suite was not rerun for this provider configuration change.
